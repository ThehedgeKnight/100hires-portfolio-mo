## Steps I Completed

1. Installed Cursor IDE — straightforward download, felt similar to other editors I've seen but never lived in
2. Found and installed the Claude Code extension through the Extensions panel (Cmd+Shift+X)
3. Found and installed the Codex extension the same way
4. Created a public GitHub repository named `100hires-portfolio-mo`
5. Cloned the repository into Cursor using the "Clone Repository" button and the HTTPS URL from GitHub
6. Opened the cloned folder in Cursor
7. Wrote this README inside Cursor's editor
8. Committed and pushed to GitHub via the terminal

## Problems I Ran Into and How I Solved Them

**Problem 1: Tried to open the zip file directly in Cursor**

My first instinct after creating the GitHub repo was to download it as a zip and open it in Cursor. That gave me a binary file error. Cursor told me it couldn't display the file because it wasn't a text format. Made sense once I thought about it. Cursor is an editor, not an extractor. I closed that, went back to the repo, copied the HTTPS URL, and used the Clone Repository option inside Cursor instead. Worked well.

**Problem 2: Not immediately sure where anything was**

Coming from tools like JIRA, SharePoint, and Braze, the layout of Cursor felt unfamiliar at first. I wasn't sure where the terminal was or how the AI panel connected to the files I was editing. I found the terminal under Cmd+J and spent a few minutes just clicking around to get oriented. It starts to make sense quickly once you stop treating it like a document editor and start thinking of it as a workspace.

## First Impressions

Cursor is genuinely interesting. Having Claude and Codex available inside the same environment where you're editing files removes a lot of the back-and-forth I normally do lik draft in Claude, copy, paste somewhere, adjust. Here it's more fluid. I'm still learning where the edges are, but the discomfort is the good kind. I've been using Claude daily in my marketing work for content, research, and workflow building, having it embedded in a coding environment opens up a different set of use cases I want to explore.

I'm not a developer. But I've spent five years building operational systems inside fast-moving teams, and I know that the fastest way to get comfortable with a tool is to use it on a real problem under a real deadline. This was a good first one.
